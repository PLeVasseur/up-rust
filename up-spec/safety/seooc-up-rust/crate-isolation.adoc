== The safety crate cannot be tainted

[.specitem,oft-sid="req~ssr-crate-isolated~1",oft-title="The safety crate cannot be tainted",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
The crate that holds the element's runtime path *MUST* be `+no_std+`, use no `+alloc+`, have no dependencies and declare no Cargo features.
So no other crate in a build can switch `+std+` or `+alloc+` on inside it.

Tokio, Protobuf and anything else that needs `+std+` *MUST* live in other crates.
--

[horizontal]
ASIL:: B
Allocated to:: the element
Verification:: gate (the manifest has no `+[features]+` and no `+[dependencies]+`; the crate builds on a sysroot with neither `+alloc+` nor `+std+`)
Status:: Draft

*Rationale.*
Cargo turns a crate's feature on for the whole build once any crate asks for it.
So only a crate with no features and no dependencies cannot have `+std+` switched on inside it by another.

With no `+alloc+`, the crate's URIs keep their authority inline, so this crate does not allocate a separate heap-owned authority representation.
That representation does not determine where a caller stores an enclosing object.

== Traffic is synchronous or polled

[.specitem,oft-sid="req~ssr-crate-sync-path~1",oft-title="Traffic is synchronous or polled",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
The runtime path *MUST* offer every traffic operation in synchronous or polled form, and *MUST* use none of `+core::future+`, `+core::task+` or `+core::pin+`.

Any async layer *MUST* sit above it, in a separate crate.
--

[horizontal]
ASIL:: B
Allocated to:: the element
Verification:: gate (a token scan for `+async+`, `+.await+`, `+Future+`, `+Pin+`, `+Poll+`, `+Waker+` and `+Context+`, and for grouped `+use core::{…}+` paths, with a negative control for each)
Status:: Draft

*Rationale.*
The runtime path keeps to a smaller part of `+core+`, with no futures, tasks or pinning, and leaves async scheduling to a layer above it.

The synchronous or polled form is the element's own product rule.
It keeps traffic independent of any executor and of library modules that a given qualification scope may not cover.

Which compiler releases, targets, library modules and options a qualification covers is stated by its supplier for an exact release (for example https://ferrous-systems.com/blog/ferrocene-26-05-0/[the Ferrocene 26.05.0 release notes]).
This item does not rest on any one such scope.
Neither the availability of a language feature nor a successful build is a qualification of the compiler or the library.

== An ASIL binary needs no crate outside its claimed graph at run time

[.specitem,oft-sid="req~ssr-crate-core-only-binary~2",oft-title="An ASIL binary needs no crate outside its claimed graph at run time",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*The claimed graph.*
An application on the ASIL path *MUST* depend at run time only on the crates of its claimed safety dependency graph:

* the safety crate;
* the bindings, wires and platform backends that its configuration qualifies as separate elements (`+aou~seooc-qualified-bindings-and-wires~5+`);
* any optional layer of the element that its configuration admits with that layer's own allocated requirements and evidence.

*Checked policy stays in the safety crate.*
The element's checked policy *MUST* be in the safety crate and usable without any optional allocation, host, application, scheduler or memory-provider layer.

An optional layer *MUST NOT* bypass or reimplement those checks.
It joins a claimed graph by its admitted evidence, never by its name or by its dependency on the safety crate.

*The graph is stated and checked.*
The graph *MUST* be stated with the configuration and checked against the final image, and the image *MUST NOT* contain code from a crate outside it.
The check judges a package by what it actually brings into the image, not by its name.

*What isolation does not do.*
The safety crate's isolation does not qualify any middleware or other crate in the graph.

*Derives.*
Derives come from `+up-rust-macros+` at compile time, and the `+unsafe+` they generate *MUST* be held to the same inventory.
--

[horizontal]
ASIL:: B
Allocated to:: the element
Verification:: gate, test
* *gate*: a symbols and dependency check of a final image against its stated graph.
* *test*
** A link fixture that uses only the safety crate and a qualified binding and wire.
** A fixture whose image brings in code from a crate outside its graph is refused.
Status:: Draft

*Rationale.*
A crate outside the claimed graph in the final image would run beside the element without meeting its requirements.

_What an application links._

* An ASIL application depends directly on `+up-rust-core+` and imports its `+up_rust_core::+` paths.
An explicit dependency alias may change that local spelling.
* The re-exports in the separate `+up-rust+` package do not make its crate root available without linking that package.
Linking it brings that package's dependencies into the graph, which the check then judges.
* An application also links the bindings and wires it uses, which are separate elements qualified on their own.
So the graph names them instead of pretending the safety crate is the whole image.
* A derive runs at compile time and leaves only generated code in the image, and that code's `+unsafe+` is inventoried like the crate's own (`+req~ssr-unsafe-inventory~3+`).

_Why the statement was corrected._
The text first raised to revision 2 also required everything the element provides to sit in the safety crate.
That left no way to admit an independently specified optional layer, such as an allocation-aware or asynchronous layer, into a later claimed configuration.
The corrected statement keeps the checked policy in the safety crate and requires an admitted optional layer to carry its own allocated requirements and evidence.

No configuration admits an optional layer at this revision.
So every current claimed graph is the safety crate with qualified bindings, wires and platform backends.

== The ASIL Streamer is its own untaintable crate

[.specitem,oft-sid="req~ssr-crate-streamer-isolated~3",oft-title="The ASIL Streamer is its own untaintable crate",oft-needs="impl,utest",oft-tags="SafetyStreamer"]
--
The ASIL Streamer's route table, admission, validation and forwarding loop *MUST* live in their own crate:

* `+no_std+`;
* no `+alloc+`;
* no Cargo features;
* no dependency other than `+up-rust-core+`;
* no 64-bit atomic type.

No feature, dependency or build setting outside it can bring classic routes, `+std+`-only paths or heap use into it.

The `+std+` loader only parses deployment data, and validation happens in this crate.

Bindings and wires are linked by the binary that uses the crate, not by the crate.
--

[horizontal]
ASIL:: B
Allocated to:: the Streamer
Verification:: gate (the same gates as `+up-rust-core+`: manifest, restricted sysroot, token scan, and its own panic-link fixture; a build for `+thumbv7m-none-eabi+`)
Status:: Draft

*Rationale.*
Separating the data plane prevents convenience dependencies or feature unification from introducing heap use into the safety path.
