[[req-ssr-memory-static]]
== ASIL-path storage is static or caller-provided

[.specitem,oft-sid="req~ssr-memory-static~3",oft-title="ASIL-path storage is static or caller-provided",oft-needs="impl,utest",oft-tags="SafetyUpRustCore,SafetyStreamer"]
--
*Where storage comes from.*
On the ASIL path (xref:README.adoc#req-ssr-element-configurations[The ASIL path and supported configurations]), the element *MUST* place all storage that its runtime path uses during initialization, from static or caller-provided memory, and *MUST* check the size, alignment and arithmetic of each placement when it makes it.

*Checks before an object is reachable.*
Before placed storage becomes reachable as an object, the element *MUST* have established that it:

* lies within its region;
* is aligned and sized for the object;
* is owned by no other live object.

The element *MUST* expose no object from a refused placement.

*Storage covered.*
The element's storage covers slots, startup slots, queues, peer and call tables, waker storage and route state, and the storage that the element provides to another part, such as the Streamer.
The Streamer owns its route table and *MUST* place it in the same way, under the same conditions and with the same checks.
The element answers for no storage of an application's own.

*Regions.*
The element *MUST* take a region only through an interface whose contract hands it the region exclusively and for the life of the process, and *MUST* check each region before it places from it.
The element then owns the region: it places from it as from any other, and it *MUST NOT* release any of it in runtime mode.
That a static or caller-provided region is exclusive and stays valid for the life of the process is the integrator's to ensure (xref:assumptions-of-use.adoc#aou-seooc-startup-storage[Startup storage that the integrator provides is exclusive and lives as long as the process]).

*Startup memory from a heap.*
The element *MUST* accept startup memory obtained from a heap only outside the ASIL path: from the memory source that an optional layer provides over the standard library's allocator, or from an allocation provider that the configuration declares (xref:../../sdk/owned-frame/providers.adoc#req-sdk-owned-frame-provider-selection[The selected memory provider is the only one used, and selecting it claims nothing] states what each is).
--

[horizontal]
ID:: `+req~ssr-memory-static~3+`
ASIL:: B
Allocated to:: the element; the Streamer, for its route table
Verification:: test, gate, review
* *test*
** A runtime path over static memory only.
** A region from a declared allocation provider placed and checked like a static one.
** Refused placements, zero-length and over-aligned requests, exposing no object.
* *gate*: the crate builds on a sysroot without `+alloc+`.
* *review*: the contract of each interface through which the element takes a region, for exclusivity and the life of the process; no release of a region in runtime mode; the Streamer's placement of its route table.
ISO 26262:: 6-Table 6 1b (part-clause numbers only)

*Rationale.*
The safety crate is `+no_std+` with no `+alloc+` (xref:crate-isolation.adoc#req-ssr-crate-isolated[The safety crate cannot be tainted]).
So its storage can come only from a static region or from bytes the caller provides.

Exclusivity is a property of live ownership, so a region may occupy addresses that an earlier, ended owner used.

[[req-ssr-memory-sealed]]
== Startup memory is sealed

[.specitem,oft-sid="req~ssr-memory-sealed~3",oft-title="Startup memory is sealed",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*When memory is sealed.*
The element *MUST* seal a startup memory when the last live setup that uses the memory enters runtime mode, and in any case when `+enter_runtime_all+` returns, whether it succeeded or failed.

*Once it is sealed.*
Once a startup memory is sealed:

* the element refuses every further placement from it, as xref:runtime-modes.adoc#req-ssr-mode-backstop[Run-time refusal only where types cannot reach] states;
* the element *MUST NOT* ask a memory source or an allocation provider for memory when it refuses a placement;
* the element *MUST* refuse a setup built on it.

A sealed startup memory stays sealed until the process ends, so a later initialization in the process needs startup memory that is not sealed (xref:runtime-modes.adoc#req-ssr-mode-one-way[There is no way back]).

*Setups still alive.*
When `+enter_runtime_all+` returns, the element *MUST* report each setup that is still alive on that memory and has not entered runtime mode.
--

[horizontal]
ID:: `+req~ssr-memory-sealed~3+`
ASIL:: B
Allocated to:: the element
Verification:: test (each case of the statement, and a setup kept alive with `+mem::forget+`), heap-window (a placement refused after sealing, asking no memory source or allocation provider for memory)

*Rationale.*
A startup memory that several setups share places nothing once initialization ends, including after a failed `+enter_runtime_all+`, which can leave some transports in runtime mode.

[[req-ssr-memory-computable]]
== Startup storage is computable before start

[.specitem,oft-sid="req~ssr-memory-computable~5",oft-title="Startup storage is computable before start",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*The computation.*
The element *MUST* provide a computation that gives, from a deployment's data alone and before the process starts, the startup memory that deployment needs.
The element *MUST* include in the result the storage for:

* the registrations of pending asynchronous operations;
* every backlog of retained owners, deferred releases and deferred destructions that its routes admit.

The element's placement at startup *MUST NOT* need more than the computation gives.

*The capacities.*
From the worst-case semantic load that the integrator declares for each route (xref:assumptions-of-use.adoc#aou-seooc-capacity-sizing[Capacities are sized for the worst case]), the element *MUST* compute the slots, queue depth, held messages and call tables that it needs.
The other capacities that this load sets are the registration storage, backlogs and startup memory that the computation gives, and the peer table that xref:../up-l1/peers.adoc#req-ssr-peer-admission[Undeclared peers cannot lock out declared ones] sizes.

*What each figure measures.*
The element *MUST* state, for each figure that it computes or reports, what the figure measures, and *MUST NOT* present it as another.
The measures are:

* usable object capacity;
* storage reserved in placed regions;
* retained backing, including what alignment, growth or a lost race leaves claimed;
* transient setup memory or stack.

A count of live objects is neither the retained backing nor the physical footprint.
A capacity that the element computes is not the QoS depth that a route declares (xref:qos.adoc#req-ssr-qos-declared[QoS is declared per route at setup]), and neither is a guarantee of what a binding's middleware has available.

*Figures that are not established.*
Where a figure depends on anything that the configuration does not bound, such as allocator overhead, scheduler storage, a thread's stack, concurrency or growth history, the element *MUST* report it as not established instead of stating a bound.
--

[horizontal]
ID:: `+req~ssr-memory-computable~5+`
ASIL:: B
Allocated to:: the element
Verification:: test, review
* *test*
** The computation against what placement used, for each route kind and for whole deployments, including registration and deferred backlogs.
** The capacities computed from a declared worst-case load against what carrying that load uses, for each route kind and for whole deployments.
** Repeated refused setups, growth histories and lost races that leave backing claimed, against what the report states.
* *review*: each reported figure's stated measure.
ISO 26262:: 6-7.4.13 (part-clause numbers only)

*Rationale.*
An integrator who places startup memory in a static region or a linker section has to size it before the process starts, and a request that does not fit is refused only at startup.
So the element provides the computation.
Each route's reserved storage is reported under xref:errors.adoc#req-ssr-error-route-report[Each route reports what it got].

_What each figure measures._
The startup memory is only part of the footprint.
A report that counted only live objects would understate two things:

* the backing that refused setups, growth and lost races leave claimed;
* the storage that asynchronous registrations and deferred work need.

Sizes that depend on a scheduler's tasks and timers, an allocator's overhead or a thread's stack depend on the supported configuration, whose package states its sizing (xref:README.adoc#req-ssr-element-configurations[The ASIL path and supported configurations]).
