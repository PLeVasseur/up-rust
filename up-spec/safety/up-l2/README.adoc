= Safety at the communication layer (uP-L2)
:toc: preamble

The key words "*MUST*", "*MUST NOT*", "*REQUIRED*", "*SHALL*", "*SHALL NOT*", "*SHOULD*", "*SHOULD NOT*", "*RECOMMENDED*", "*MAY*", and "*OPTIONAL*" in this document are to be interpreted as described in https://www.rfc-editor.org/info/bcp14[IETF BCP14 (RFC2119 & RFC8174)]

Conventions, layout and tags: xref:../README.adoc[the safety area's README].

This part is the safety counterpart of xref:../../up-l2/README.adoc[the Communication Layer (uP-L2)] and of xref:../../up-l2/dispatchers/README.adoc[its dispatchers].
It holds two things:

* interaction: what the element guarantees for an RPC call and for the identity of a message;
* forwarding: what the Streamer guarantees when it carries messages between transports, and what a deployment provides to operate it.

== Whom the items bind

NOTE: Where an item is filed says which layer it concerns (xref:../README.adoc#filing[filing and scope]).

* *The element and the Streamer.*
The items here were written for the up-rust SEooC (xref:../seooc-up-rust/README.adoc[its README]) and for the Streamer, a part of its own that is built on the element's carrier primitives (xref:streamer.adoc#req-ssr-streamer-scope[What the Streamer is, and the bounded-runtime Streamer profile]).
They are not protocol requirements of uP-L2, and none of them names an SDK or a dispatcher of another language.
* *Requirements.*
Each requirement's statement says whom it binds (xref:../README.adoc#req-ssr-requirements-bind[A requirement binds the actors to which it gives a duty]): the element, the Streamer, and, where a statement gives them a duty, the Streamer binary and the suppliers of the Streamer and of the Streamer binary.
+
NOTE: Its tags say which repositories cover it (xref:../README.adoc#tags[the tags]).

* *Assumptions of use.*
The four assumptions of use filed here are that element's: three about operating its Streamer, and one about message IDs that never repeat across restarts.
Whom they bind: xref:../seooc-up-rust/assumptions-of-use.adoc#aou-seooc-assumptions-bind[An assumption of use binds the integrator who claims the scope, and replaces no requirement].
* *The protocol chapter.*
The protocol chapter stays in force for what it covers (xref:../README.adoc#req-ssr-contract-transition[What a part declares and claims, and when a replacement takes effect]).
* *The dispatcher chapter.*
For the Streamer, which follows the bounded-runtime Streamer profile (xref:streamer.adoc#req-ssr-streamer-scope[What the Streamer is, and the bounded-runtime Streamer profile]), two items replace rules of xref:../../up-l2/dispatchers/README.adoc[the dispatcher chapter], and each names the rule, the behaviour and the implementation for which it does so: xref:streamer.adoc#req-ssr-streamer-dispatch-obligations[Undeliverable messages are counted, never sent as dead letters] replaces rules of `+dsn~dispatcher-at-least-once~1+` and `+dsn~dispatcher-dead-letter-topic~1+` and the chapter's rule that a dispatcher provides an API to start and stop dispatching per topic where the uP-L1 delivery method is push, and xref:streamer.adoc#req-ssr-streamer-rpc-error-response[An RPC request that cannot be dispatched is answered, best effort] replaces `+dsn~dispatcher-rpc-error-response~1+`.
Those rules stay in force for every other dispatcher, a uStreamer that does not follow that profile included.

== Items filed with the element

NOTE: Some items that concern this layer are filed with the element, because they are rules of its own modes, memory, build and reports.
In their statements, some of these name the Streamer, its binary or a binding, alone or beside the element, and the asynchronous layer where a statement gives it a duty (xref:../README.adoc#req-ssr-requirements-bind[A requirement binds the actors to which it gives a duty]).

They are in xref:../seooc-up-rust/README.adoc[the element's part]:

* QoS, TTL and deadlines of a route (xref:../seooc-up-rust/qos.adoc[`qos.adoc`]);
* refusals, errors and route reports (xref:../seooc-up-rust/errors.adoc[`errors.adoc`]);
* the check of a role's resource ID (xref:../seooc-up-rust/deployment-data.adoc#req-ssr-config-resource-ranges[Resource IDs are checked at setup]);
* the asynchronous interface's contract (xref:../seooc-up-rust/build.adoc#req-ssr-async-seam[The asynchronous interface has a written, executor-independent contract]);
* the Streamer's crate and its build (xref:../seooc-up-rust/crate-isolation.adoc#req-ssr-crate-streamer-isolated[The ASIL Streamer is its own untaintable crate]; xref:../seooc-up-rust/build.adoc#req-ssr-build-panic-abort[The ASIL build aborts on panic and checks overflow]; xref:../seooc-up-rust/build.adoc#req-ssr-build-specified-functions-only[The ASIL build contains only specified functions]);
* the end-to-end protection wire, with the hops a protected frame survives (xref:../seooc-up-rust/e2e-wire.adoc#req-ssr-e2e-survives-hops[Protection survives every allowed hop] in xref:../seooc-up-rust/e2e-wire.adoc[`e2e-wire.adoc`]);
* how the application reacts to what the element reports (xref:../seooc-up-rust/assumptions-of-use.adoc#aou-seooc-application-reacts[The application reacts to what the element reports]).

A carrier route that crosses integrity levels upward is a transport-layer rule: xref:../up-l1/integrity.adoc#req-ssr-integrity-carrier-crossing[Upward carrier crossings copy once, or are refused] in xref:../up-l1/integrity.adoc[integrity levels].
