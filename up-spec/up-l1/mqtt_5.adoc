== Overview

[NOTE]
====
MQTT is an OASIS standard: a protocol for publish/subscribe messaging in the Internet of Things (IoT). It is designed to need very little code on a device and very little network bandwidth, which suits it to connecting remote devices. Many industries use it, among them telecommunications, manufacturing, automotive, and oil and gas.

For more information, please refer to https://mqtt.org/
====

This document defines how MQTT 5 PUBLISH packets can be used to transfer uProtocol messages (UMessages) between uEntities for the following use cases:

1. *uEntity-2-uEntity*: Communication between uEntities within the same vehicle by means of an _in-vehicle_ MQTT broker.
2. *Device-2-Device* (D2D): Communication between uEntities in vehicles and a (cloud) back end system by means of an _off-vehicle_ MQTT broker, e.g. running in the back end. The mapping for this use case uses a coarser grained topic structure than the one for in-vehicle only communication.

NOTE: MQTT itself limits the number of levels in a Topic Name or Topic Filter only through the maximum length of a UTF-8 Encoded String, 65,535 bytes (source: MQTT Version 5.0, edition of 7 March 2019, sections 1.5.4 UTF-8 Encoded String and 4.7.3 Topic semantic and usage). A limit that a particular broker imposes is a matter of that broker's deployment, not of this mapping.

== UMessage Mapping

NOTE: A uProtocol message consists of _UAttributes_ and optional payload. The following sections define how these are mapped to/from an MQTT 5 PUBLISH packet.

=== UAttributes

[.specitem,oft-sid="dsn~up-transport-mqtt5-attributes-mapping~3",oft-covers="req~utransport-send-preserve-data~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
An MQTT 5 PUBLISH packet that is used to convey a uProtocol message *MUST*
contain properties as defined in <<mqtt5-uattributes-mapping,uAttributes Mapping to MQTT 5 PUBLISH Properties>> (source: MQTT Version 5.0, edition of 7 March 2019, section 3.3.2.3 PUBLISH Properties).
Unless a mapping row defines presence explicitly, a property *MUST* be present
if and only if the corresponding UMessage attribute has a non-empty value.
--

[#mqtt5-uattributes-mapping]
.uAttributes Mapping to MQTT 5 PUBLISH Properties
[cols="1,2,5"]
|===
| uAttributes Property
| PUBLISH Packet Property
| Description

| N/A
| User Property [key: _uP_]
a| The uProtocol version being used

* *MUST* be set to the (major) version of the uProtocol specification that the message mapping adheres to (`1` for major version 1).
* Message consumers *MAY* use this property to determine that the (PUBLISH) packet contains a uProtocol message.

| _id_
| User Property [key: _1_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the lower-case https://www.rfc-editor.org/rfc/rfc9562#section-4[hyphenated string representation] of the UUID (source: RFC 9562, section 4 UUID Format).

| _type_
| User Property [key: _2_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the value of the _uprotocol.ce_name_ option defined for the
link:../up-core-api/uprotocol/v1/uattributes.proto[UMessageType enum].

| _source_
| User Property [key: _3_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the xref:../basics/uri.adoc#uri-definition[string serialization of the UUri]

| _sink_
| User Property [key: _4_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the xref:../basics/uri.adoc#uri-definition[string serialization of the UUri]

| _priority_
| User Property [key: _5_]
a| The message's priority class as defined in xref:../basics/upriority.adoc[Message Priority]

* *MUST* be set to the value of the _uprotocol.ce_name_ option defined for the
link:../up-core-api/uprotocol/v1/uattributes.proto[UPriority enum].

| _ttl_
| User Property [key: _6_] +
_Message Expiry Interval_

a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

If _ttl_ is `0`, the message has no expiration. The _Message Expiry Interval_
and TTL User Property *MUST NOT* be set in this case. MQTT applies no expiry to
a message whose _Message Expiry Interval_ is absent, whereas an interval of `0`
is a lifetime of zero seconds, not an unlimited lifetime
(source: MQTT Version 5.0, edition of 7 March 2019, section 3.3.2.3.3 Message Expiry Interval).

If _ttl_ is greater than `0`, the _Message Expiry Interval_ property *MUST* be set to

stem:[expiry := ceil(ttl/1000)].

For every positive _ttl_, the TTL User Property *MUST* be set to the original
value of _ttl_ in milliseconds, including values that are multiples of 1000.
MQTT servers reduce the _Message Expiry Interval_ as a message waits for onward
delivery, so that property alone cannot preserve the original TTL even when it
has whole-second precision. The receiving side *MUST* use the original TTL User
Property together with the message creation timestamp to apply uProtocol expiry.
A received _Message Expiry Interval_ of `0` *MUST NOT* become a non-expiring
uProtocol message.

For compatibility with legacy publishers that omit the TTL User Property, a
receiver *MAY* use the received expiry interval converted to milliseconds as a
conservative TTL bound. This fallback does not recover the original TTL and can
expire a message earlier; conversion *MUST NOT* overflow or produce an unlimited
lifetime from a finite expiry interval.

| _permissionLevel_
| User Property [key: _7_]
a| The service consumer's permission level as defined in xref:../basics/permissions.adoc#_code_based_access_permissions_caps[Code-Based Access Permissions (CAPs)]

* *MUST* be set to the xref:../basics/permissions.adoc#_code_based_access_permissions_caps[CAP] value's decimal string representation. 

| _commStatus_
| User Property [key: _8_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the link:../up-core-api/uprotocol/v1/ucode.proto[UCode enum] integer value's decimal string representation.

| _reqId_
| _Correlation Data_
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the UUID's 16 byte representation in big endian order.

| _token_
| User Property [key: _10_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the token value.

| _traceparent_
| User Property [key: _11_]
a| Defined in xref:../basics/uattributes.adoc[uProtocol Attributes (UAttributes)].

* *MUST* be set to the traceparent value.

| _payload_encoding_id_
| _Content Type_
a| The identifier defined in the
xref:../basics/payload_encoding_registry.adoc[payload-encoding registry]

* _Content Type_ *MUST* be present if and only if the UMessage `payload` field
  is present, including a present zero-length payload.
* When present, _Content Type_ *MUST* be the identifier's decimal string
  representation.
* When reconstructing a UMessage, a present _Content Type_ yields a present
  `payload` (the PUBLISH packet payload, possibly zero-length) and a present
  `_payload_encoding_id_`; an absent _Content Type_ yields both fields absent
  and requires an empty PUBLISH packet payload.
* A receiver *MUST* reject a _Content Type_ value that is not a decimal
  unsigned integer or is greater than `65535`. All other validity and
  interpretation rules are those of the `payloadEncodingId` attribute; this
  binding does not add or restate them.

NOTE: The numeric identifier minimizes the size of the PUBLISH packet.

|===

== MQTT Topic Structure

NOTE: Message producers publish messages to _topics_ maintained by an MQTT broker. Other clients can then subscribe to such topics in order to receive the messages that are being published to these topics.

=== uEntity-2-uEntity Communication

[.specitem,oft-sid="dsn~up-transport-mqtt5-e2e-topic-names~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
The topic name of an MQTT 5 PUBLISH packet containing a _Publish_ UMessage that is published to an _in-vehicle_ broker **MUST** consist of the following segments (source: MQTT Version 5.0, edition of 7 March 2019, sections 3.3.2.1 Topic Name and 4.7.1.1 Topic level separator):

`{source.authority}/{source.ue_type}/{source.ue_instance}/{source.ue_version}/{source.resource}`

The topic name of an MQTT 5 PUBLISH packet containing a _Notification_, _RPC Request_ or _RPC Response_ UMessage that is published to an _in-vehicle_ broker **MUST** consist of the following segments (source: MQTT Version 5.0, edition of 7 March 2019, sections 3.3.2.1 Topic Name and 4.7.1.1 Topic level separator):

`{source.authority}/{source.ue_type}/{source.ue_instance}/{source.ue_version}/{source.resource}/{sink.authority}/{sink.ue_type}/{sink.ue_instance}/{sink.ue_version}/{sink.resource}`
--

Please refer to <<UUri Encoding Rules>> for details regarding the encoding of the `source` and `sink` UUris into the topic's segments.

=== Device-2-Device Communication

[.specitem,oft-sid="dsn~up-transport-mqtt5-d2d-topic-names~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
The topic name of an MQTT 5 PUBLISH packet containing a UMessage that is published to an _off-vehicle_ broker **MUST** consist of the following segments (source: MQTT Version 5.0, edition of 7 March 2019, sections 3.3.2.1 Topic Name and 4.7.1.1 Topic level separator):

`{source.authority}/{sink.authority}`
--

Please refer to <<UUri Encoding Rules>> for details regarding the encoding of the source and sink UUris into topic segments.

==== Examples

.Sending any UMessage to a back end
====
The MQTT 5 topic name used by uEntities with authority name `vehicle1` for sending any type of UMessage to uEntities with authority name `backend` via an _off-vehicle_ broker is

`vehicle1/backend`
====

.Receiving all UMessages in a back end
====
The MQTT 5 topic filter used by uEntities with authority name `backend` for receiving all types of UMessages from uEntities with arbitrary authority names via an _off-vehicle_ broker is

`+/backend`
====

=== UUri Encoding Rules

The table below contains the rules for encoding a UUri's fields into an MQTT topic name's or filter's segments.

[cols="2,2,6"]
|===
| Topic Segment
| UUri Field
| Encoding

|`authority`
|`authority_name`
a| The segment *MUST* contain the (UTF8) string representation of the 

1. `+` (`U+002B`, Plus Sign) character, if the authority name is the xref:../basics/uri.adoc#pattern-matching[wildcard authority].
2. name of the host/authority that the (local) uEntity is running on, if authority name is empty.
3. authority name, otherwise.

|`ue_type`
|`ue_type_id`
a| The segment *MUST* contain the (UTF8) string representation of the

1. `+` (`U+002B`, Plus Sign) character, if the uEntity type identifier is the xref:../basics/uri.adoc#pattern-matching[wildcard type ID].
2. the upper-case https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the uEntity type identifier with all leading `0` characters omitted.

|`ue_instance`
|`ue_instance_id`
a| The segment *MUST* contain the (UTF8) string representation of the

1. `+` (`U+002B`, Plus Sign) character, if the uEntity instance identifier is the xref:../basics/uri.adoc#pattern-matching[wildcard instance ID].
2. the upper-case https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the uEntity instance identifier with all leading `0` characters omitted.

|`ue_version`
|`ue_version_major`
a| The segment *MUST* contain the (UTF8) string representation of the

1. `+` (`U+002B`, Plus Sign) character, if the uEntity major version is the xref:../basics/uri.adoc#pattern-matching[wildcard version].
2. the upper-case https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the uEntity major version with all leading `0` characters omitted.

|`resource`
|`resource_id`
a| The segment *MUST* contain the (UTF8) string representation of the

1. `+` (`U+002B`, Plus Sign) character, if the resource identifier is the xref:../basics/uri.adoc#pattern-matching[wildcard resource ID].
2. the upper-case https://www.rfc-editor.org/rfc/rfc4648#section-8[base16 encoding] of the resource identifier with all leading `0` characters omitted.

|===

== Connection Handling

[.specitem,oft-sid="req~up-transport-mqtt5-session-config~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Each transport implementing this specification *MUST* provide means to configure the value of the https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html#_Toc3901048[Session Expiry Interval] property and the value of the https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html#_Toc3901039[Clean Start] flag of the MQTT CONNECT packet being used when establishing a connection to a broker (source: MQTT Version 5.0, edition of 7 March 2019, section 3.1.2.4 Clean Start and section 3.1.2.11.2 Session Expiry Interval).
--

[.specitem,oft-sid="req~up-transport-mqtt5-reconnection~1",oft-needs="impl,utest",oft-tags="TransportLayerImpl"]
--
Each transport implementing this specification *MUST*

* re-establish a lost connection to an MQTT broker using an exponential backoff strategy.
* re-subscribe to all previously subscribed topics, if the broker indicates that https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html#_Toc3901078[no session is present] after successful reconnection (source: MQTT Version 5.0, edition of 7 March 2019, section 3.2.2.1.1 Session Present).
--

.Backoff values for reconnecting to a broker
====
The following table provides some guidance for implementation:

[cols="3,2,2,2,2,2"]
|===
| Reconnect attempt | 1 | 2 | 3 | 4 | n > 4
| Backoff (ms)      | `500` | `1000` | `2000` | `4000` | `10000`
|===
