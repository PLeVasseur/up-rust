====

NOTE: The native wire carries a value as it lies in memory (xref:README.adoc#req-ssr-wire-scope[What a wire is, and the wire contract]).
A sender initializes the value in the storage that carries it, and a receiver borrows it there (<<req-ssr-native-in-place,A native payload is written and read where it is carried, or its route is refused>>).
The value is not encoded or decoded.

This page holds:

* the three requirements that say what a native payload type is, that it is read only under its exactly agreed layout, and that it is written and read in place;
* the rules of other pages that a native route rests on, in the order in which a payload meets them (<<index>>);
* what fails, and where (<<failures>>);
* what establishes each property (<<boundary>>);
* one way to establish a layout identity (<<guidance>>).

== Whom the items bind

Each item's statement says whom it binds (xref:../../contract-generations.adoc#req-ssr-requirements-bind[A requirement binds the actors to which it gives a duty]).

* A binding carries a native route as it carries any other (xref:../bindings.adoc#req-ssr-binding-lent-storage[Lent storage is exclusive, disjoint and stable for as long as it is held]).
It does not know the type.
* The choice of a wire and of a transport: xref:../payload-paths.adoc#independent[a wire and a transport are chosen apart].
* A wire from elsewhere that hands out views of shared memory is not the native wire, and it is no part of the element (xref:README.adoc#req-ssr-wire-scope[What a wire is, and the wire contract], "A separate element").
What its integrator owes for its `+unsafe+` code: xref:../../safety/elements/up-rust/assumptions-of-use.adoc#aou-seooc-qualified-bindings-and-wires[Bindings and wires pass their contracts].

== Words

* A *native type* is a type that <<req-ssr-native-type,A native payload type holds its whole value in one fixed layout>> admits.
* A *native route*: xref:README.adoc#req-ssr-wire-scope[What a wire is, and the wire contract], "Native and serialized routes".
* A *layout identity*: <<req-ssr-native-agreement,A native type is read only under its exactly agreed layout>>, "Layout identity".
* A *native agreement*, or *agreement* on this page: <<req-ssr-native-agreement,A native type is read only under its exactly agreed layout>>, "Agreed by the deployment".
* The *Rust-only native domain* is defined in <<req-ssr-native-agreement,A native type is read only under its exactly agreed layout>>, "Only between binaries that use the element".
* A *view* is a typed, read-only borrow of the storage in which a frame arrived (<<req-ssr-native-in-place,A native payload is written and read where it is carried, or its route is refused>>, "Receiving").

[[req-ssr-native-type]]
== A native payload type holds its whole value in one fixed layout

[.specitem,oft-sid="req~ssr-native-type~3",oft-title="A native payload type holds its whole value in one fixed layout",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
The element answers for each duty of this item, apart from the derive's refusal in "Decided from the declaration".

*What a native type is.*
A type that a native route carries *MUST* hold its whole value in one contiguous block of memory.
Its declaration *MUST* fix the size, the alignment and the place of every field for an ABI, and leave none of them to the compiler's choice.

*What it cannot hold.*
A native type *MUST NOT* hold:

* a pointer, a reference, an address or a handle of any kind;
* a field with an invalid bit pattern (xref:../integrity.adoc#req-ssr-integrity-any-bits[In-place types accept every bit pattern]);
* a value that runs a destructor when it ends (xref:../runtime.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits]);
* a field whose size or place depends on the value.

*Handles.*
A handle is a value of a type that stands for a resource of an operating system, of a process or of a middleware: a descriptor, a socket, a mapping, a lock, a thread or a process.
No such type is native, whether or not its values would mean something in another process.
A loan, a lease and a frame are the element's local interfaces for owning storage.
They stand outside every payload, and none of them is a native type or a field of one.
A number that names something, such as an index or an identifier, is carried as a number: carrying it is no pointer, transfers no ownership and gives no access, and the element *MUST NOT* give a received number any meaning as a resource.

*Size zero, and unions.*
The element *MAY* admit as native a type of size zero, and a union where this item admits each of its fields.
The permission obliges no implementation and no derive to admit every such type, and the element *MUST* state truthfully which of them it admits.
The frames of a type of size zero are present payloads of length zero (xref:../payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding]), and storage lent for one is lent as storage of zero bytes is (xref:../bindings.adoc#req-ssr-binding-lent-storage[Lent storage is exclusive, disjoint and stable for as long as it is held], "An empty payload").
Both are native only inside the Rust-only native domain (<<req-ssr-native-agreement,A native type is read only under its exactly agreed layout>>, "Only between binaries that use the element").

*Padding.*
A native type *MAY* have padding.
Padding bytes have no meaning in a native representation: no layout identity names their contents, and two values that differ only in them are the same value.
The element *MUST NOT* let a read, a view, a comparison, a rule of equality or a serialization that it makes depend on the contents of padding bytes.
Nothing in this item requires padding bytes to be zero, to be equal or to be read.

*The payload.*
A native payload is the value itself.
The element *MUST NOT* send the address of a value, of a buffer or of a shared-memory segment as a payload, or in place of one.

*Decided from the declaration.*
The element *MUST* treat a type as native only where one of these made it so:

* the derive, which *MUST* refuse at build time a type that breaks this item;
* an `+unsafe+` declaration that states these obligations and sits in a reviewed inventory (xref:../../safety/assurance.adoc#req-ssr-unsafe-inventory[Every `unsafe` is inventoried and justified]).

*Size.*
The encoded size of a native type is the type's size in memory, and its alignment is the type's alignment.
Wherever the element declares or reports a size or an alignment for a native type, it *MUST* give those values, and the size as exact.

Allocated to:: the element; the derive, for refusing at build time a type that breaks this item
Verification:: compile-fail, test, review, gate
* *compile-fail*
** The derive's refusal of each kind of field that this item forbids, one case for each, with a control that compiles: a pointer, a reference, a type that stands for a resource, a loan, a lease, a frame, a field with an invalid bit pattern, a field with a destructor, and a field whose size depends on the value.
* *test* or *compile-fail*: a type of size zero and a union that the element states that it does not admit: neither is treated as native, refused at setup (test) or at build time (compile-fail).
* *test*
** A type that the derive accepts: its size, its alignment and the place of each field, compared with its layout as built and with what the element declares and reports for it.
** A type of size zero and a union that the element states that it admits: each is native, and a frame of the first is a present payload of length zero.
** Two frames of a type with padding, each built as bytes, that differ only in their padding bytes: every comparison and every view that the element makes gives the same result for both, and no case requires padding bytes to be zero, to be equal or to be read.
** A value sent on a native route: the frame's payload is the value's bytes, with no address of a value, of a buffer or of a shared-memory segment in their place.
* *review*: each `+unsafe+` declaration of a native type, against the obligations of this item; and the element's statement of the types of size zero and the unions that it admits, against what its derive accepts.
* *gate*: the inventory check, which refuses a new or changed declaration until it is reviewed.

*Rationale.*
A view lets a reader use bytes that another process wrote as a value of a type.
That is sound only for a type whose every property the reader can rely on without trusting the writer.

_No address._
An address means something only in the address space that produced it.
A receiver that followed one would read memory that the sender never meant, and no check at the receiver can tell.

_No handle._
A handle names a resource that someone owns and someone closes.
It is useful only together with facts that its bits do not carry: how long it stays valid, who owns the resource and who closes it, and what a peer's death does to it.
A native value is its bytes alone, so no handle is native.
A loan, a lease and a frame are the element's own interfaces for owning storage, and they travel in no payload.
A ban of some handles only would leave a type's author to judge which ones are safe, and the derive could not check that judgement, so safe code would be trusted to keep the ban.

_No invalid bit pattern, no destructor._
A faulty writer can leave any bytes in a frame.
A type that accepts every bit pattern turns that into a wrong value, which end-to-end protection can catch, and never into undefined behaviour.
A type with a destructor would run code when a slot is overwritten, which a native route does not allow.

_Size zero, unions and padding._
Inside the Rust-only native domain, a writer and a reader lay out and read a value under one layout rule, so a type of size zero and a union are sound to view there.
Another language can lay out such a type, or read it, differently, so they stay inside that domain.
Padding can hold any bytes, so nothing reads a meaning into it.

_The two ways._
A wire is written in safe code, and the element's memory safety does not depend on it (xref:README.adoc#req-ssr-unsafe-wire-untrusted[No wire can break the element's memory safety]).
The derive checks a type, and a reviewer checks an inventoried `+unsafe+` declaration.
A wire's description of a type is neither a derive nor a reviewed declaration, so it makes no type native.

[[req-ssr-native-agreement]]
== A native type is read only under its exactly agreed layout

[.specitem,oft-sid="req~ssr-native-agreement~3",oft-title="A native type is read only under its exactly agreed layout",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*Layout identity.*
The _layout identity_ of a native type is everything that decides how its bytes are read:

* which type it is, by the name under which a deployment agrees it;
* its complete layout: its size, its alignment, and the place, the size and the scalar type of every field.

Two layout identities are the same only where every part is the same.
The ABI that a layout holds for is agreed beside it, by the fingerprint.
Exchanging the fingerprint is a duty of each binding that carries native frames between processes, and comparing it is the element's: both are stated in xref:../peers.adoc#req-ssr-native-abi-agreed[A native representation never crosses an ABI].

*Only between binaries that use the element.*
A layout identity is stated for types of the up-rust element.
A native route is agreed only between binaries that use the element; they are the _Rust-only native domain_ of a deployment.
A payload of a C or a C++ program is not native under this item.
Nothing widens that: not a declaration that fixes a C layout, and not a tool that generates or reads declarations of another language.
A binary outside that domain is reached through a serialized wire (xref:serialized.adoc[serialized wires, and the values they own]).

*Agreed by the deployment.*
A _native agreement_ is the deployment data that names, for each native route, the route's type with its layout identity, the ABI for which it states that layout, and the payload encoding identifier that the frames of the route carry.
The integrator supplies it, and chooses that identifier as the registry's rules for originating one allow (xref:../../safety/elements/up-rust/assumptions-of-use.adoc#aou-seooc-deployment-data[Deployment data is in range, verified and protected]; xref:README.adoc#encoding-identifier[the encoding identifier is the registry's]).

* The element *MUST* prepare a native route only for a type that the agreement names for that route, with its layout identity.
* The element *MUST* make each check of this item itself: what an agreement declares stands in for no check of a layout or of an identity.
* The element *MUST* send each frame of a native route with the payload encoding identifier that the agreement names for the route (xref:../payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding], "On sending").
* The agreement is part of a native route's configuration, which is fixed at setup: that nothing changes it in runtime mode is stated in xref:../../basics/resources.adoc#req-ssr-mode-no-setup-at-runtime[Setup is impossible in runtime mode].

*At setup.*
The element *MUST* refuse a native route at setup, naming the route and the type, where:

* the deployment has not agreed the type;
* the layout identity of the type as it is built differs in any part from the agreed one;
* the agreement states its layouts for another ABI than the one that the element is built for.

*Before a view.*
The element *MUST* give a reader a view of a frame only where it has established, before any reader can see the frame, that the frame comes from a writer whose layout identity for the route is the reader's, and whose ABI is the reader's (xref:../integrity.adoc#req-ssr-integrity-checked-at-admission[In-place frames are checked once, at admission]).

* Where that is not established for a frame, the element *MUST* refuse the frame and count it.
* Where the element cannot establish it for a route at all, the element *MUST* refuse the route at setup, by name.

*A complete comparison.*
A comparison establishes it only where it tells every two different layout identities apart.

* To establish it, the element *MUST* compare the complete layout identities, or a value computed from each for which the element states, with its argument, that two different layout identities do not share it.
* A value that is too short for such an argument establishes nothing.
The element *MAY* use one to select which agreed layout a frame is compared with.
It *MUST* still refuse a frame for which the complete comparison fails, or was not made.
* An equal size and an equal alignment establish nothing.
* An equal payload encoding identifier and an equal ABI fingerprint establish nothing about a layout.

*Three identities.*
The payload encoding identifier, the layout identity and the ABI fingerprint say three different things:

* the identifier says that the payload is a native representation under this deployment's agreement;
* the layout identity says which type, with which complete layout;
* the fingerprint says for which ABI.

The element *MUST NOT* take one of them for another.

*What agreement shows.*
An established layout identity shows that a writer and a reader read the same bytes in the same way.
It does not show that the bytes of a frame are the value that the writer meant: a faulty writer can write any bytes.
That a view is sound whatever the bytes are rests on <<req-ssr-native-type,A native payload type holds its whole value in one fixed layout>>, on the element's own checks and on xref:../integrity.adoc#req-ssr-integrity-zero-copy[Zero-copy only from a writer at or above the reader].

*The mechanism.*
This item leaves to the implementation which table, digest or algorithm is used, if any, where a layout identity is kept or carried, and when it is compared before a view.
--

ID:: `+req~ssr-native-agreement~3+`
ASIL:: B
Allocated to:: the element
Verification:: test, fault-injection, review
* *test*
** At setup: a type that the deployment has not agreed; a type whose layout as built differs from the agreed one in each part in turn, which are its name, its size, its alignment, and one field's place, size and scalar type; and an agreement for another ABI. Each is refused by name.
** A writer whose layout identity differs from the reader's in each of those parts in turn: no frame of it reaches a reader, and each is refused and counted, or the writer's side is refused.
** Two layouts of equal size and equal alignment and different fields: a frame of the one never reaches a reader of the other.
** Where the element uses a short value to select a layout: two different layouts that are built to share that value, with the frame still refused.
** A frame with the route's layout identity and another payload encoding identifier: refused (xref:../payload-paths.adoc#req-ssr-wire-encoding-checked[A wire is given only a payload of its own encoding]).
** A frame sent on a native route carries the payload encoding identifier that the agreement names for the route.
* *fault-injection*: a peer that is built for another layout of a type, on real processes.
* *review*: the comparison and its argument: that it covers every part of a layout identity, that it is made before a view for every writer whose frames a reader can get, and, where a computed value is compared, why two different layout identities do not share it.

*Rationale.*
Two processes can read one block of memory as the same value only if they agree on its layout exactly.
The payload encoding identifier cannot carry that agreement: the registry says that an identifier does not name a type or a layout (xref:../../basics/payload_encoding_registry.adoc#type-identity[the payload encoding registry, "Encoding Identity versus Type Identity"]).

_Exact agreement._
Two layouts can have the same size and the same alignment, and still place different fields at the same bytes.
A reader that took one for the other would deliver wrong values on every frame, with no error.

_A short value._
A short value can be equal for two different layouts.
It is useful for picking, among several agreed layouts, the one to compare with.
It cannot stand in for the comparison, however rarely two layouts share it.

_Three identities._
A deployment can carry many native types under one private-use identifier, one type can exist with two layouts, and one layout can be built for two ABIs.
Each of the three values tells one of these apart, and none tells another's.

_The mechanism._
This item requires the outcome, and <<guidance>> describes one way to reach it.

[[req-ssr-native-in-place]]
== A native payload is written and read where it is carried, or its route is refused

[.specitem,oft-sid="req~ssr-native-in-place~2",oft-title="A native payload is written and read where it is carried, or its route is refused",oft-needs="impl,utest",oft-tags="SafetyUpRustCore"]
--
*Sending.*
On a native route the element *MUST* have the sender initialize the value once, directly in the storage that carries it (xref:../payload-paths.adoc#req-ssr-payload-written-once[A payload is written once, into the storage that carries it]), and *MUST* ensure that:

* nothing is read from a loan before it is written, and a loan is sent only once the whole value has been written into it;
* sending consumes the loan, and ends the sender's access to the storage (xref:../bindings.adoc#req-ssr-binding-lent-storage[Lent storage is exclusive, disjoint and stable for as long as it is held]);
* a loan whose lease is dropped unsent is given back, exactly once (xref:../runtime.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else]);
* no pending operation holds a loan (xref:../../up-l2/execution.adoc#req-ssr-async-seam[The asynchronous interface has a written, executor-independent contract]).

*Receiving.*
The element *MUST* give a receiver a checked, typed view of the storage in which the frame arrived, wherever xref:../integrity.adoc#req-ssr-integrity-zero-copy[Zero-copy only from a writer at or above the reader] allows a view and <<req-ssr-native-agreement,A native type is read only under its exactly agreed layout>> is established, and *MUST* ensure that:

* the view does not live longer than the lease of its frame;
* nothing can be written through it;
* when that lease is dropped, the frame is given back, exactly once (what the binding's return of it may do: xref:../bindings.adoc#req-ssr-binding-frame-drop[What a received frame's destructor may do]).

*A forgotten lease.*
Safe code can forget the lease of a loan or of a frame, and then no transition ends it.
The element *MUST* keep the loan or the frame charged to its route for the life of the process.
The element *MUST NOT* return its storage, hand it out or deliver it again, or give it a second owner.
What the binding owes for the storage that it lends is stated apart, in xref:../bindings.adoc#req-ssr-binding-lent-storage[Lent storage is exclusive, disjoint and stable for as long as it is held], and neither duty rests on the other.
The element *MUST* meet each rule of this item without relying on a destructor to run.

*The only copies.*
Which copies of a payload a route may take, each chosen at setup and reported, is stated for every route in xref:../payload-paths.adoc#req-ssr-payload-written-once[A payload is written once, into the storage that carries it] and xref:../payload-paths.adoc#req-ssr-payload-route-form[A route's form is fixed at setup, by what the route declares and never by a name], and for the copy route in xref:../integrity.adoc#req-ssr-integrity-zero-copy[Zero-copy only from a writer at or above the reader].
Those rules hold for a native payload as for any other.
What a carrier copies when it forwards a native frame is stated with the carrier (xref:../../up-l2/streamer.adoc#req-ssr-streamer-byte-identity[Carriage keeps the bytes]; xref:../integrity.adoc#req-ssr-integrity-carrier-crossing[Upward carrier crossings copy once, or are refused]).

*No substitute.*
The element *MUST NOT* serve a native route by a serialized encoding, by a staged copy or by a conversion of the representation.
The element *MUST NOT* admit a native route that cannot be prepared as this item states.
How such a route is refused at setup, with the route and the missing capability named, and that no operation in runtime mode changes a route's form, is stated in xref:../payload-paths.adoc#req-ssr-payload-route-form[A route's form is fixed at setup, by what the route declares and never by a name].

*Resources.*
On every path of a native route, success, refusal, cancellation, a peer's failure and a frame's return among them, heap use, panics, work and waits are governed by:

* xref:../payload-paths.adoc#req-ssr-heap-none[No heap in runtime mode on a native path];
* xref:../bindings.adoc#req-ssr-binding-no-heap[Binding code allocates nothing in runtime mode on a native path];
* xref:../../basics/error_model.adoc#req-ssr-refuse-before-heap[Refuse before touching the heap];
* xref:../../basics/error_model.adoc#req-ssr-refuse-no-panic[No panic on runtime paths];
* xref:../runtime.adoc#req-ssr-bound-work[Work per call is bounded by setup data];
* xref:../runtime.adoc#req-ssr-bound-wait[Every bounded wait has a logical deadline];
* xref:../peers.adoc#req-ssr-peer-failure-normal[Peer failure is normal input].
--

[horizontal]
ID:: `+req~ssr-native-in-place~2+`
ASIL:: B
Allocated to:: the element
Verification:: test, compile-fail, miri, review
* *test*
** A native route on a lending test double and on each real lending binding: the value is read at the address at which it arrived.
** A loan that was not written whole, which cannot be sent, and a write after a send, which does not compile.
** A loan whose lease is dropped unsent, and a frame whose lease is dropped: each goes back once, counted by the test double.
** A loan and a frame whose leases safe code forgot: each is still charged at the end of the run, and its storage is never returned, and never lent or delivered again.
** A native route on a binding that cannot serve it: not admitted, and refused at setup, with no serialized or copied route in its place.
* *compile-fail*: a write through a view, and a view used after the lease of its frame is dropped.
* *miri*: the view, on a lending test double, with a forgotten lease.
* *review*: no path from a native route into an encoder, a decoder or a staging buffer, and no property of this item that holds only if a destructor runs.

*Rationale.*
A native route exists so that a value crosses between processes with no allocation, no code that could fail on its contents, and no copy other than one that setup chose and reported.
A deployment that chooses one relies on exactly that.

_Written where it is carried._
A value that was built elsewhere and then copied into the loan would still arrive.
The copy would cost time in proportion to the payload, and a place to build the value first.

_A forgotten lease._
Forgetting a lease is safe code, and it runs no destructor (source: the standard library documentation, Rust 1.98.1, `+std::mem::forget+`, its description and its section "Safety": https://doc.rust-lang.org/1.98.1/std/mem/fn.forget.html#safety[`+std::mem::forget+`]).
The rule for a forgotten lease is the same for every lease of the element (xref:../runtime.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else]; xref:../runtime.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits]).

_No substitute._
An implementation could keep a route working by falling back to a serialized encoding or to a copy.
Values would still arrive, and a test of values would pass.
The route would then allocate, or take longer, in the case that the deployment did not plan for.

_A handoff binding._
A binding that cannot lend takes one copy at the hand-off, and the route's report says handed off.
That is the same representation, copied once, and it is no serialization.

[[guidance]]
== One way to establish a layout identity

.A built-in table of layouts, checked at setup
====
* *A table fixed when a binary is built.*
A deployment can write its agreement as a table that lists each native type with a canonical description of its layout.
A table that is built in can be reviewed as one file, and nothing at run time changes it.
* *Deriving the layout again at setup.*
The element can compute the description of a type's layout from the type as it is compiled, and compare it with the table.
That finds a table that no longer matches the code before any frame.
* *Comparing between the two sides.*
Each side of a route can record its complete description, or a digest of it that comes with a collision argument, where the other side reads it when the route is prepared.
The ABI fingerprint is exchanged in the same way.
* *A short value on each frame.*
A few bytes taken from a layout's description can tell the frames of several agreed types apart at little cost.
Such a value can select which agreed layout a frame is compared with, and <<req-ssr-native-agreement,A native type is read only under its exactly agreed layout>>, "A complete comparison", states which comparison establishes that a writer's layout identity is the reader's.
====
