= Owned-frame SDK: the parts an application selects, and memory providers
:toc: preamble

The key words "*MUST*", "*MUST NOT*", "*REQUIRED*", "*SHALL*", "*SHALL NOT*", "*SHOULD*", "*SHOULD NOT*", "*RECOMMENDED*", "*MAY*", and "*OPTIONAL*" in this document are to be interpreted as described in https://www.rfc-editor.org/info/bcp14[IETF BCP14 (RFC2119 & RFC8174)]

Conventions and tags: xref:README.adoc[the owned-frame SDK area's README].
Whom each item binds: xref:README.adoc#req-sdk-owned-frame-contract[The owned-frame SDK contract binds the parts that declare it].

This page holds what an SDK offers for the parts that an application selects for its owned-frame routes, and the contract between an SDK and the memory providers that supply its memory.
Its items say which provider a request goes to, what a provider states, who owns what a provider supplies, and what a refusal leaves.

[[req-sdk-owned-frame-extension-public]]
== A part that an application selects is selected through public interfaces alone

[.specitem,oft-sid="req~sdk-owned-frame-extension-public~1",oft-title="A part that an application selects is selected through public interfaces alone",oft-needs="impl,utest,uman",oft-tags="OwnedFrameSdk"]
--
*The parts.*
An application selects, for the owned-frame routes of an SDK, parts that the SDK did not have to ship: a memory provider, a binding, a wire, a platform backend, a scheduler integration or an adapter.

*Public.*
For each kind of such part that it lets an application select, the SDK *MUST* offer the selection through public, documented interfaces, so that a part that any party writes against those interfaces and their documentation alone can be selected.

*What selection needs none of.*
For that selection, the SDK *MUST NOT* require any of these:

* a change to the SDK's source;
* an interface that is not public;
* a registration that only the SDK's own parts, or parts that its supplier approves, can make;
* presence in a list of parts that the SDK's supplier keeps.

Building, linking or registering a part through a documented mechanism that is open to every party is none of these.

*Not by name.*
The SDK *MUST NOT* admit or refuse a selected part because of its name, its origin or its packaging.
It admits a part by what the part declares and by the setup checks that items state.
Selecting a part waives neither the part's own contract nor any setup check that an item states.
For a route, xref:../../safety/up-l1/payload-paths.adoc#req-ssr-payload-route-form[A route's form is fixed at setup, by what the route declares and never by a name] states this of the names of its wire, its payload encoding and its middleware.

*Each part's own contract.*
What a selected part does is stated by its own contract.
Where the SDK's core is the element, the contracts of a binding, a wire and a platform backend are these:

* a binding: xref:../../safety/up-l1/bindings.adoc#req-ssr-binding-scope[What a binding is, and the binding contract];
* a wire: xref:../../safety/up-l1/wires.adoc#req-ssr-wire-scope[What a wire is, and the wire contract];
* a platform backend of the element, or one that an integrator supplies for the element: xref:../../safety/seooc-up-rust/platform.adoc#req-ssr-platform-contract[Every platform backend of the element keeps the platform's rules], which states the duties of both and says where the integrator's own are stated.

For every SDK, the contracts of the other kinds are these:

* a memory provider: <<req-sdk-owned-frame-provider-contract,A memory provider states the contract that the SDK relies on>>; <<req-sdk-owned-frame-provider-ownership,Memory from a provider stays valid while it is held, and is disposed of once under its provider's contract>>; <<req-sdk-owned-frame-provider-failure,A provider's refusal reaches the caller with its cause, and leaves held memory valid>>;
* a scheduler integration: xref:application.adoc#req-sdk-owned-frame-scheduler-integration[A scheduler integration supplies wake-ups, timers and contexts through public interfaces];
* an adapter: xref:README.adoc#req-sdk-owned-frame-adapter[An adapter keeps a message whole across a crossing, or refuses it by name].

This item gives a selected part no duty.
--

Verification:: test, review
* *test*
** For each kind of part that the SDK lets an application select: a part built outside the SDK's source, against its public interfaces and their documentation alone, selected and used.

* *review*

Applications run on targets and middleware that the supplier of an SDK cannot all foresee, so the part that fits a target is often written by another party.
A selection that needed the SDK's source, a private interface or a privileged list would make every such part wait on the SDK's supplier, or fork the SDK.
A name, an origin or a packaging says nothing about what a part does, while its declaration and the setup checks do.
Each kind of part keeps its own contract, so selecting a part neither adds to its duties nor lifts them.

[[req-sdk-owned-frame-provider-selection]]
== The selected memory provider is the only one used, and selecting it claims nothing

[.specitem,oft-sid="req~sdk-owned-frame-provider-selection~1",oft-title="The selected memory provider is the only one used, and selecting it claims nothing",oft-needs="impl,utest,uman",oft-tags="OwnedFrameSdk"]
--
*A memory provider.*
A memory provider is a part that supplies memory to the SDK.
A memory source hands over regions for startup memory, and an allocation provider serves requests to acquire, resize and release memory.
One part can be both.
The sources that a memory provider states that it draws on (<<req-sdk-owned-frame-provider-contract,A memory provider states the contract that the SDK relies on>>) are part of that provider.

*Explicit.*
Where the SDK's core, or a layer above its core, takes memory from a memory provider for an operation, the SDK *MUST* send each request to the provider that the application selected for that operation or, where it selected none for the operation, to the provider that it selected for the object that the operation belongs to.
The SDK *MUST NOT* let a later change of a default redirect the requests or the releases of an object whose provider is already selected.

*A layer that selects.*
A layer that takes memory from one stated provider on the application's behalf, such as a layer that obtains startup memory from the host's heap, is the application's selection of that provider.
Such a layer *MUST* state in its documentation that provider, its allocation domain, and when the selection takes effect.

*No other domain.*
Where the selected provider refuses a request, the SDK *MUST NOT* send the request to another provider, to an allocation provider that the application did not select or to any other allocation domain, and *MUST NOT* satisfy it from one.
Where the core is the element, a route's allocation is outside this clause: xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-declared[The heap class is declared, with no default] states how it stays in its domain.

*Without a provider.*
How the element stays usable without a memory-provider layer, on static or caller-provided memory: xref:../../safety/seooc-up-rust/crate-isolation.adoc#req-ssr-crate-core-only-binary[The checked policy stays in the safety crate, and no admitted optional layer bypasses or reimplements it]; xref:../../safety/seooc-up-rust/startup-memory.adoc#req-ssr-memory-static[ASIL-path storage is static or caller-provided].

*No claim.*
Selecting a memory provider admits no allocation on a route and establishes no guarantee.
How a route's allocation is admitted: xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-declared[The heap class is declared, with no default]; xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-none[No heap in runtime mode on a native path].
How a guarantee is established: xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-guarantees[A stronger resource guarantee is required by name, and admitted or refused].
--

[horizontal]
ID:: `+req~sdk-owned-frame-provider-selection~1+`
Allocated to:: the SDK, for each request that its core or a layer above its core makes to a memory provider, a route's allocation excepted from "No other domain" where its core is the element; each layer that takes memory from one stated provider on the application's behalf, for stating in its documentation that provider, its allocation domain and when the selection takes effect
Verification:: test, review
* *test*
** Two instrumented providers in one process, selected for different operations or objects: each request sent to its own selected provider.
** A provider selected for an object and another for one of its operations: that operation's requests sent to the operation's provider.
** A default changed after an object's provider was selected: the object's requests and releases still sent to that provider.
** The selected provider refusing a request, other than a route's allocation where the core is the element, while another provider and an allocation provider that the application did not select have memory: the request neither sent to nor satisfied from either of them.
** A selected provider that draws on sources that it states: each request of the SDK sent to that provider, and none sent by the SDK to one of those sources or to another allocation domain.
* *review*
** Each operation of the core and of each layer above it that takes memory from a memory provider, and the provider to which it sends each request.
** Each layer that takes memory from one stated provider on the application's behalf: its documentation states that provider, its allocation domain and when the selection takes effect.
** No path that sends a refused request, other than a route's allocation where the core is the element, to another allocation domain, or satisfies it from one.

*Rationale.*
An application chooses a provider for what it knows of its memory: where it lies, what bounds it and what exhaustion does.
Memory taken from anywhere else has none of those properties, and a fallback after a refusal would hide the very exhaustion that a bounded provider makes visible.
A default that changed later would move an existing object's memory to a domain that its owner never chose.
A layer that takes memory on the application's behalf is itself the application's choice, so its documentation names the provider that comes with it.
A provider built over other sources is chosen with them, so drawing on them is no fallback.
Which allocation a route admits, and which guarantee it holds, rest on the route's declaration and on evidence, and the choice of a provider supplies neither.

[[req-sdk-owned-frame-provider-contract]]
== A memory provider states the contract that the SDK relies on

[.specitem,oft-sid="req~sdk-owned-frame-provider-contract~1",oft-title="A memory provider states the contract that the SDK relies on",oft-needs="impl,utest,uman",oft-tags="OwnedFrameProvider"]
--
*What it states.*
A memory provider *MUST* state, in the documentation that is released with it, for each configuration or range of parameters that it supports:

* its resource and failure policy, with each point that xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-declared[The heap class is declared, with no default] lists for a policy, an unknown point stated as unknown;
* its allocation domains: where its memory comes from, the sources that it draws on, and what bounds it;
* the requests that it admits: sizes, alignments and limits, what a request of size zero does, and what an inadmissible request does;
* the conditions under which what it hands over stays valid, and who owns it;
* the state that it is in after a refusal;
* whether released memory becomes available again, and what it keeps for the life of the process;
* whether a resize can wait, and for what;
* whether it supports a call made while another of its calls is in progress.

*Unknown and not stated.*
Where a bound of its allocation domains is not known, the provider *MUST* state it as unknown.
A context, a condition of validity or ownership, or a call made while another is in progress, that the provider does not state as supported, is not supported.

*True on every path.*
The provider *MUST* make what it states hold for every acquisition, resize and release that a request can reach under the stated conditions, its own dependencies included.
The provider *MUST* state, as its resource and failure policy, the one that its allocator's stated contract establishes, as xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-declared[The heap class is declared, with no default] states of a policy.

*What relies on it.*
What the element's setup and a route's declared policy take from a provider's stated contract: xref:../../safety/seooc-up-rust/runtime-modes.adoc#req-ssr-mode-init-failure[Initialization failure]; xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-declared[The heap class is declared, with no default].

*Not evidence.*
What a provider states establishes no guarantee (xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-guarantees[A stronger resource guarantee is required by name, and admitted or refused]).
--

[horizontal]
ID:: `+req~sdk-owned-frame-provider-contract~1+`
Allocated to:: each memory provider
Verification:: review, test
* *review*
** The provider's statement, point by point and configuration by configuration, against the provider's code and its dependencies for every acquisition, resize and release that a request can reach.
** Each point of its resource and failure policy, and each bound of its allocation domains, stated or stated as unknown; the contexts, the conditions of validity and ownership, and calls made while another is in progress, stated as supported or left out.
** A stated panic or end of the process, read in the statement and in the code rather than provoked.
* *test*: each failure behaviour that the provider states and that a test can provoke without ending the process, for each configuration that it supports: exhaustion, an inadmissible request, a request of size zero, a refused resize, the provider's state after a refusal, and a wait where one is stated.

*Rationale.*
The SDK's setup decides what it can rely on from a provider, and a route's declared policy states what its provider does, so both are only as true as the provider's own account.
An allocation interface that returns an error can still end the process on exhaustion or wait for a lock, and only the provider can say which it does.
The points of a resource and failure policy are listed once, with the heap class, and the provider states each of them for every configuration that it supports.
A point stated as unknown is read as unknown, where a point left out invites the favourable reading.
The SDK cannot use memory safely under conditions of validity, ownership or calling that nobody states, so what is not stated there is not supported.
An account that held only for a first request, or without the provider's dependencies, would fail on growth, on release or on a lock deep in a dependency.

[[req-sdk-owned-frame-provider-ownership]]
== Memory from a provider stays valid while it is held, and is disposed of once under its provider's contract

[.specitem,oft-sid="req~sdk-owned-frame-provider-ownership~1",oft-title="Memory from a provider stays valid while it is held, and is disposed of once under its provider's contract",oft-needs="impl,utest",oft-tags="OwnedFrameSdk,OwnedFrameProvider"]
--
*The SDK's calls.*
The SDK *MUST* call a memory provider, from its core or from a layer above its core, only from the contexts and under the conditions that the provider's statement supports (<<req-sdk-owned-frame-provider-contract,A memory provider states the contract that the SDK relies on>>).

*The end of a hold.*
When an object or an operation of the SDK's core, or of a layer above its core, that holds a block from an allocation provider ends its hold, the SDK *MUST* do exactly one of these with the block:

* release it once, to the provider that supplied it or through a handle that the provider's contract makes equivalent to it, with what that contract requires of a release;
* pass it to one other owner;
* keep it, where the contract of that object or operation states that it retains the block.

The SDK *MUST NOT* release to a provider memory that the provider did not supply.
The SDK *MUST NOT* use a block through a handle that a release or a successful resize has made invalid.
Where the core is the element, a route's allocation is outside this clause: xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits] states how it is destroyed once.

*What a block needs.*
With each block from an allocation provider that it holds or passes to another owner, the SDK *MUST* keep what every later use and the final release of the block need: the provider or a handle that its contract makes equivalent, the description of the block that a release requires, and access to the provider's state, also after the SDK object that made the block has ended.
While its core or a layer above its core holds a block, and while an owner to which it passed the block holds it, the SDK *MUST NOT* end a condition under which the provider's statement keeps the block valid.

*Regions.*
How the element holds a region that a memory source hands over for startup memory, for the life of the process: xref:../../safety/seooc-up-rust/startup-memory.adoc#req-ssr-memory-static[ASIL-path storage is static or caller-provided]; xref:../../safety/seooc-up-rust/startup-memory.adoc#req-ssr-memory-sealed[Startup memory is sealed].
The SDK *MUST* use a region that a memory source hands over for startup memory only for as long as the source's statement says that it hands the region over, where a layer above its core takes the region or where its core is not the element.

*Forgotten owners.*
Where the SDK's core is the element, that nothing that its core holds is reused while it is still owned, a forgotten owner included, is stated in xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-slot-types[A decoded value is destroyed once, as its route's class admits] and xref:../../safety/seooc-up-rust/release.adoc#req-ssr-release-lease-drop[A lease gives back its slot and nothing else].
Where its core is not the element, the SDK *MUST NOT* release, reuse or give to another owner a block whose owner has not ended its hold, a forgotten owner included; where its core is the element, the SDK *MUST NOT* do so with a block that a layer above its core holds.

*The provider.*
On a successful request, a memory provider *MUST* hand over storage that has the request's size, alignment and initialization, and that overlaps no storage that another owner holds.
The provider *MUST* keep each block that it has handed over valid, and given to no other owner, until the block is released, for as long as the conditions of validity that its statement states hold.
The provider *MUST* keep each region that it has handed over for startup memory valid, and given to no other owner, for as long as its statement says that it hands the region over.
The provider *MUST NOT* move or invalidate a block that is held, except in a resize that the block's owner requests.
A successful resize replaces the block as the provider's contract states.
When it refuses a resize, the provider *MUST* leave the block valid, with its owner and its contents unchanged.
The provider *MUST NOT* change a block or a region that is held when it serves or releases another request.
--

*Rationale.*
A block released to a provider that did not supply it corrupts that provider's bookkeeping.
A block released twice, or used after its release, can be handed to another owner while it is still in use.
A provider's contract can make two handles equivalent, so a release needs the right provider and not the same handle.
A block that changes owner, or outlives the object that made it, still needs its provider and its description for a correct release.
The SDK relies on each block and region staying valid and in place for as long as it is held, and only the provider can keep that true while it serves other requests.
A provider whose own terms could end a block's validity while it is held would make the SDK's hold worthless, so validity lasts until the release, under conditions that the SDK leaves in place.
A region that a source hands over for a stated period is valid for that period only, so a hold that outlived it would reach memory that the source has taken back.
An owner that asks for a resize accepts that the block may move, and a refused resize leaves it where it was.
A forgotten owner still holds what it owned, so nothing that it held can be reused behind it.
A provider called from a context that it does not support can break any of this, whatever its code does in other contexts.

[[req-sdk-owned-frame-provider-failure]]
== A provider's refusal reaches the caller with its cause, and leaves held memory valid

[.specitem,oft-sid="req~sdk-owned-frame-provider-failure~1",oft-title="A provider's refusal reaches the caller with its cause, and leaves held memory valid",oft-needs="impl,utest,uman",oft-tags="OwnedFrameSdk,OwnedFrameProvider"]
--
*The core.*
Where the SDK's core is the element, what its setup does with a provider's refusal is stated in xref:../../safety/seooc-up-rust/runtime-modes.adoc#req-ssr-mode-init-failure[Initialization failure], and what a route does with one in runtime mode in xref:../../safety/seooc-up-rust/errors.adoc#req-ssr-refuse-before-heap[Refuse before touching the heap].
Where the SDK's core is not the element, the core *MUST* meet, for each of its operations that takes memory from a memory provider, each duty that this item gives a layer above the core.

*A layer above the core.*
Where a memory provider returns a refusal to a request of an operation of a layer above the core, the layer *MUST* fail that operation with a result that names the provider's refusal as its cause.
The layer *MUST NOT* panic or end the process in its own handling of the refusal.
The layer *MUST NOT* release or invalidate memory that an earlier, successful step still owns.

*What happens to a caller's value.*
For each value that an operation takes from its caller, the layer *MUST* state in its documentation each disposition that a refusal can give the value: handed back to the caller unchanged, ended once, or retained under a stated policy.
On a refusal, the layer *MUST* give each such value one of the dispositions stated for it, and *MUST* say in the operation's result which one it gave.
The layer *MUST* hand back unchanged each value that the result reports as handed back.

*Before the request.*
Where the provider's statement lets a request panic or end the process for a condition that the layer can check, the layer *MUST* exclude that condition before it sends the request, or refuse the operation by name.
A request that meets the provider's conditions can still be refused for want of memory.

*The provider.*
When a memory provider refuses a request, it *MUST* leave every block and region that it has handed over and that is held valid and unchanged.

*What a refusal is not.*
How the element uses a provider whose stated contract lets a request wait or end the process: xref:../../safety/seooc-up-rust/runtime-modes.adoc#req-ssr-mode-init-failure[Initialization failure]; xref:../../safety/seooc-up-rust/heap.adoc#req-ssr-heap-guarantees[A stronger resource guarantee is required by name, and admitted or refused].
--

ID:: `+req~sdk-owned-frame-provider-failure~1+`
Allocated to:: the core of an SDK whose core is not the element, and each layer above the core, for their operations that take memory from a memory provider; each memory provider
Verification:: test, review
* *test*
** A provider test double that refuses, in turn, each request that the core of an SDK whose core is not the element and each layer above the core sends it: the operation fails with a result that names the provider's refusal as its cause, each value that its caller gave it receives a disposition stated for it and the result says which, the process neither panics nor ends, and no memory that an earlier, successful step owns is released or invalidated.
** A value that a result reports as handed back: handed back unchanged.
** A request with a condition that the provider's statement lets panic or end the process, and that the layer can check: the condition excluded before the request, or the operation refused by name with the request never sent.
** A request that meets the provider's conditions and is refused for want of memory: reported as the provider's refusal.
** After a provider's refusal: every block and region that it handed over and that is held still valid and unchanged.
* *review*
** The documentation of each such operation: the dispositions that a refusal can give each value that the operation takes from its caller.
** Each path from a provider's refusal to the operation's result, with no panic and no end of the process in the layer's or the core's own handling.

*Rationale.*
Above the core, a provider's refusal is ordinary: a pool that is full, a request that is too large.
An application can react to it only if it learns that the provider refused, and knows what became of what it handed in.
A disposition stated before the value is taken, and reported when it happens, is one that the caller can rely on, where a report written afterwards could describe anything.
A panic or a process end in the layer's own handling would turn a recoverable refusal into the loss of the process.
A provider that ends the process itself does so under its stated contract, which the layer cannot change.
Releasing memory that an earlier step still owns would turn one failed operation into a fault in another.
Checking a request against the provider's conditions keeps a request that the provider would answer with a panic or a process end from being sent at all, while a well-formed request can still meet a full pool.
